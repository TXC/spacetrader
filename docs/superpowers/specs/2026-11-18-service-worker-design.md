# Space Trader: the service worker, in TypeScript

Date: 2026-11-18. Step 9 of the
[review roadmap](../plans/2026-11-18-review-roadmap.md).
Findings T6 and O1 to O4 of
[the code review](../../code-review-2026-11-17.md).

## Intent

The game works without a connection after one visit. The code that
makes this happen, `public/sw.js`, is plain JavaScript outside the
build, so it is not type-checked, and it never changes between builds.
Because it never changes:

- the browser never replaces it, so files from old builds are never
  cleared and pile up;
- files without a hash in their name, such as the icons and the
  manifest, are never refreshed;
- every page load downloads again what is already stored.

## Goals

- The worker is written in TypeScript, type-checked and linted.
- After a new build, players get the new version, and files of old
  builds are removed.
- Nothing is downloaded twice.
- A game in progress is never reloaded under the player.

## Non-goals

- Notifications, background sync, or an "install" button of our own.
- Working offline before the first visit has finished loading.

## Anti-goals

- A page reload in the middle of an encounter.
- A player stuck on an old or half-updated version.

## What exists today

- `public/sw.js`, about 60 lines: network first for the page, stored
  copy first for everything else, one fixed store named
  `spacetrader-v1`.
- `src/offline.ts`: registers the worker in production builds, and
  after every load sends it the list of files the page loaded.
- `scripts/check-offline.mjs`, run by `pnpm test:offline`: builds,
  serves the build, and checks four things with the network off.
- `public/manifest.json`: 112 icon entries, none marked as usable for
  Android's shaped icons, no theme colour, `fullscreen` display.

## Approaches

**A. `vite-plugin-pwa`, with a worker we write ourselves
(recommended).** The plugin builds `src/sw.ts` and hands it the exact
list of files in the build, each with a fingerprint. Our worker stores
that list and removes anything not on it. We keep control of the
worker's behaviour; the plugin does the part that is easy to get wrong.
Version 2 of the plugin supports this Vite version. It brings two
packages of the Workbox library with it.

**B. The same plugin, writing the worker for us.** No worker code of
our own, but its behaviour is set through options, which is the control
the owner asked to keep.

**C. Our own build step, no plugin.** A small script that writes the
file list into the worker after the build. No dependency, but we would
write and test the storing, the clean-up and the update ourselves.

## Design

### The worker

`src/sw.ts`, built to `sw.js`:

- When it is installed, it stores every file of the build, from the
  list the build gives it.
- When it takes over, it removes stored files that are not on the
  list.
- A request for the page is answered from the store, so the game starts
  with no connection. Everything else on the list is answered from the
  store too.
- A request for something not on the list goes to the network.

The message from the page listing loaded files is no longer needed, so
`src/offline.ts` shrinks to the registration.

### When players get a new version

A new worker installs in the background while the game is open. It
takes over only once every tab of the game has been closed, so the next
time the game is opened it is the new version. Nothing reloads during
play, and nobody is asked anything.

### The manifest

Written in `vite.config.ts` and generated by the plugin, so its file
names always match the build:

- icons: 192 and 512 pixels;
- a theme colour for light and one for dark;
- `standalone` display, which keeps the phone's status bar. Today's
  `fullscreen` hides the clock and battery, which is unusual for a game
  that is mostly text.

The 26 `apple-touch-icon` lines in `index.html` are cut to the three
sizes iOS asks for.

### Type checking and lint

A third TypeScript project, `tsconfig.worker.json`, checks `src/sw.ts`
against the worker's own environment, not the page's. The lint rules
for plain scripts added in step 2 are pointed at it.

### Tests

`scripts/check-offline.mjs` keeps its four checks and gains three:

- after the first load, the store holds exactly the files of the build;
- a second load downloads nothing that is already stored;
- after a second, changed build is served and the game is reopened, the
  new version is shown and the old build's files are gone.

The script starts the preview server through Vite's own interface in
place of a fixed 2.5-second wait, and always shuts it down.

## Left to the builder

- The plugin's options beyond those named here.
- How the second build for the test is made to differ.

## Approved

The owner approved this design on 2026-11-18, with every recommendation
in it.

## What the build did differently

- **The pictures the build makes are stored too.** The first list held
  only scripts, styles and the page, and the offline check caught the
  title picture missing.
- **The icons used only for installing are not stored**, except the two
  the manifest names. The other files in `public/PWAImages` are left in
  place but nothing refers to most of them any more.
- **The offline check makes its own two builds**, so `pnpm test:offline`
  no longer runs `pnpm build` first.
- **A fourth update check was added:** the open game is not replaced
  while it is open.
